# ATM 出钞模块安全指令层（Java 模拟实现）

针对“撬开机柜、小电脑直挂出钞模块数据线发送出钞指令”这一真实黑盒攻击，
用纯 Java（零外部依赖，仅 JDK 内置密码学）重写业务软件与出钞模块之间的指令层，
并以硬件模拟 + 攻击测试验证：**任何未被主机授权的指令都无法驱动机械出钞。**

## 一、威胁模型

假设攻击者已经具备物理接入能力，可以：

- 撬开机柜，把自有设备接到出钞模块的数据总线（USB/RS-485 等）；
- 窃听全部总线流量、注入任意伪造帧、重放历史帧、篡改字节后重发；
- 中间人（MITM）拦截、替换、丢弃帧；
- 整体替换业务软件所在的电脑；
- 在维修更换模块/电脑时尝试混入恶意设备；
- 利用断网窗口发起离线交易欺诈。

攻击者**不持有**任何合法密钥，也无法触发出钞模块机身内部的物理配对开关。

安全判据只有一个：模拟机械层的实际出钞金额，必须严格等于主机授权交易金额之和。

## 二、核心设计决策

### 1. 全对称密码体系，适配弱算力模块

出钞模块（低端 MCU）只运行对称算法，不做任何非对称运算：

- **AES-256-GCM**：总线帧的认证加密，同时保证机密性、完整性、来源真实性；
- **HMAC-SHA256 / HKDF**：密钥派生与配对确认；
- **SHA-256**：离线日志哈希链。

每台模块在产线由 KMS 注入唯一的密钥派生主密钥 `KDK`（存于模拟安全存储），
再按用途域隔离派生：

| 派生密钥 | 用途 |
|----------|------|
| `K_PAIR` | 配对协议票据校验 |
| `K_CHANNEL` | 总线业务帧 GCM 通道 |
| `K_AUTH` | 主机授权令牌的本地验证 |

一个用途的密钥泄露不影响其他用途。密钥永不在总线上明文出现。

### 2. 每笔出钞必须绑定主机授权令牌

业务终端只是令牌的“搬运工”，自身**没有任何让模块出钞的授权能力**。
出钞命令携带的 `AuthToken` 由银行主机（KMS/HSM 域）用 `K_AUTH` 密封，
出钞模块本地验证：

- **在线令牌**：与单笔 `txnId` + 金额强绑定，命令金额与令牌金额不符即拒；
- **离线预算令牌**：时间窗 + 累计额度 + 单笔上限，模块本地记账强制执行。

因此即使攻击者完全控制业务电脑，也伪造不出能通过模块校验的令牌。

### 3. 安全配对：物理门控 + 一次性票据 + 单调序号

维修更换时的重新配对流程：

1. 维修人员现场拨动模块机身内配对开关（双人授权），模块进入**短时效配对模式**，
   断电/超时自动退出；**总线消息无法触发配对模式**；
2. KMS 按维修工单签发一次性 `PairingTicket`（用模块 `K_PAIR` 密封，
   AAD 绑定模块 ID、终端 ID、单调 `pairSeq`、过期时间）；
3. KDK 信封用**终端身份主密钥**密封，只有工单指定的终端能打开；
4. 双向挑战-应答（HMAC 证明双方都持有正确派生密钥）后才建立通道；
5. 模块内 `pairSeq` 严格单调递增并持久化，旧工单重放、跨设备票据挪用一律拒绝。

### 4. 防重放：计数器窗口 + 交易去重，且失败不污染状态

- GCM 帧带单调计数器，接收端维护“最大序号 + 位图滑动窗口”，识别重放与乱序；
- **关键安全性质：只有 GCM 认证通过的帧才推进接收状态**。伪造/篡改帧在解密阶段
  即被拒绝，计数器、位图、额度、去重缓存均不变化，攻击者无法用垃圾帧扰乱窗口；
- 出钞命令再叠加 `txnId` 去重缓存（持久化），同一交易绝不第二次出钞（幂等）；
- 重同步帧本身仍须通过 GCM 认证，且只允许有限前跳，防止计数器被恶意推高。

### 5. 离线交易：预签预算 + 本地记账 + 哈希链审计

- 断网前主机下发离线预算凭证（时间窗、累计额度、单笔上限）；
- 模块在 NVM 中持久化已花额度、单调索引与哈希链日志，断网期间本地强制额度；
- 每条日志携带前一条哈希，条目哈希随日志一并持久化；
  启动自检与重连对账时重算并与**存储的原始哈希**比对，任何删除/改写/断链即发现；
- 终端与模块各维护一条相同的链，重连后互相印证。

## 三、模块与包结构

```
src/com/atm/
├── crypto/      Crypto(AES-GCM/HMAC/HKDF/SHA256)、KeyLabel
├── protocol/    TLV 编解码、帧类型/字段常量、Result/ResultCode
├── bus/         BusFrame、PhysicalBus(可嗅探/注入/MITM)、BusDevice
├── security/    DeviceKeys、SecureChannel、PairingTicket、AuthToken、
│                Kms、OfflineLog、NonVolatileStore
├── hardware/    HardwareSimulator(钞箱/出钞机械，安全判据来源)
├── dispenser/   CashDispenser（弱算力模块固件，信任根侧）
├── terminal/    TerminalApp（业务终端软件）、终端持久化
├── attacker/    AttackerDevice（攻击者小电脑，9 类攻击能力）
├── demo/        AttackDemo（端到端攻防叙事）
└── tests/       5 个测试套件 + 极简零依赖测试框架
```

## 五、构建与运行

需要 JDK 17+（在 JDK 21 验证），无需 Maven/Gradle 或任何第三方库。

```bash
./build.sh           # 编译并运行全部 53 个测试
./build.sh compile   # 仅编译
./build.sh demo      # 编译 + 测试 + 端到端攻防演示
```

演示结尾会比对“主机授权金额合计”与“机械实际出钞合计”，一致即证明所有攻击均未产生未授权出钞。

## 六、关键安全不变量

1. 没有通过 GCM 认证的帧，不改变任何安全状态；
2. 没有有效主机授权令牌的出钞命令，机械层不动作；
3. 配对模式只能由物理操作进入，总线无法触发；
4. 配对序号单调递增，票据一次性、短时效、绑定设备与终端；
5. 同一 `txnId` 幂等，离线额度与哈希链持久化、可审计、防篡改；
6. 广播总线按目标标识过滤，非本机/非配对来源的帧静默丢弃。
